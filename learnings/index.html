Learnings

We run a two-court venue on software we wrote. Real bookings, real money, one WhatsApp number that also carries the login. Things break, and each one teaches something a tutorial would not. These are short: what happened, what it taught us, the rule now. One entry per failure, written the week it happens, as a ritual rather than a retrospective.

How these are written

Each entry starts from the record: a commit, a log line, a message in the chat where the mistake was caught. The figures are the real ones. Where Claude Code made the mistake, it says so; where I did, it says that. Customer names never appear. The rule at the end is the part we keep, usually as a test, sometimes as a sentence in the rules file the agent reads before every session.
