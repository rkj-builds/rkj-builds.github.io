A missing feature can wait. A wrong value being written cannot

The rebuilt bookings page went live with a written list of what it did not do yet. Two things were fixed first, because they were not gaps. They were lies.

Where
The bookings page, rebuilt
Cost
Nothing, which was the point
The rule
Ship with a known gap list, and fix before shipping only what writes something false.

What happened

The rebuild had six things the old page did that the new one did not. The alternative to shipping was a restoration pass on all six before anyone had touched the new screen. Rahul's call: go live, run it for a few days, fix what actually hurts, one change at a time, so a working page is never traded for a speculative one.

Two defects were fixed before the ship anyway. The page was switching off the server's sixty-minute guard against double-sending reminders. And bulk "mark paid" defaulted to cash, inventing a channel that lands in the drawer reconciliation.

What it taught us

Real use is a better filter for which gaps matter than my ranking was. But the rule that separated the two fixes from the gap list is the one worth keeping: a missing feature makes someone wait; a wrong value being written makes the books wrong.

The rule now

The gap list lives in the pull request, read before anything is added to the page. The biggest gaps are still open and known: no restore for a cancel, the pay-first flag invisible, court pooling that ignores sport.
