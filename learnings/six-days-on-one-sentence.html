Six days on a one-sentence error

"Could not create the renewal." That was the whole error. The real reason was in a server log nobody was reading, and the first fix we shipped was for a different bug.

Where
Memberships, renewals
Cost
Six days, one wrong migration, and renewals refused the whole time
The rule
When a write fails, get the database's own message before theorising. Two blockers can stack.

What happened

The renewal insert wrote the source as "manual". The column's check constraint allows seven values, and "manual" is not one of them. Postgres refused it every time with a code and a message. The handler swallowed both and returned one flat sentence.

A unique index was suspected, a migration was written and run, and renewals still failed. The wrong fix looked plausible because nothing on screen could contradict it. The index was also real; fixing it and seeing the same error did not mean the diagnosis was wrong. It meant the error text was useless.

What it taught us

A refusal must name the reason. The cost of a vague error is not the bug, it is every confident wrong theory built on top of it.

The rule now

Database refusals put the code and the message into the response, so a screenshot of the dialog is enough to diagnose. Literals are checked against the column's constraints, not against what reads naturally, and a test pins the allowed values to the column.
