The application desk

How I use AI on a job application. A small crew of Claude Code agents reads the posting, drafts from facts I can show, checks every claim, and hands me the result. It never sends anything.

Chess.com's form asks how AI was used on the application. This page is the answer: the workflow, the scores it got, and where it still falls short. It's a sibling of the captain, a crew of Claude Code agents that works my design queue at Travelopia (Slack, Jira, GitHub) and drafts replies in my voice, and it runs on the same rule. They draft. I decide.

The problem

An answer on an application form can go wrong in three ways. It claims something I can't show. It sounds like everyone else's. Or it's about me, when the question was about them.

A model that drafts fast makes all three easier. So the desk is built to stop each one before I read the draft.

1. It knows the work, and only the work

The desk reads one file of facts: each project, what I did, and every figure with the page it came from. The figures trace back to one table that every surface of my portfolio uses. If two of my own pages disagree, the file lists the conflict instead of picking the better number. Building it found ten.

There's a second file for what I like, what I don't, and what I won't do. It's empty until I write it. Until then, a draft that needs a feeling leaves a placeholder with my name on it, rather than inventing one.

The third source is how I write and decide. The captain had already studied my Slack, Jira and pull-request writing and the calls I make in design reviews. The desk reads that study: the measured shape of my sentences, and the things I argue for, like metric first and every state built before a form is called done. The writer takes its point of view from those, not from thin air. Nothing internal from that study reaches a draft: no names, no tickets, no figures.

2. Four agents, one question at a time

  • ScoutSorts postings by my own rules: remote from India, or a move that's sponsored. It quotes the line in the posting that decides.
  • ReaderReads the posting like the person who wrote it: what they really need, ranked; what's hard about the job; what's unknown; and where I'm thin.
  • WriterDrafts one answer, with a point of view about the people the company builds for. Every fact in it has a row saying where it came from.
  • EditorIt checks each claim against the source and scores the draft. Then it hands the answer to an agent that knows nothing, to see what a stranger takes from it.

3. The editor doesn't trust the writer

Five scores, 1 to 5: true, specific, about them, short and no clichés. Any false claim fails the draft, whatever the rest says. Then the cold read: a fresh agent gets only the question and the answer, and says what this person does, what it would remember tomorrow, and which phrases sound like filler.

Its first real job was Chess.com's "What gets you excited about this role?". It took three drafts. The first left their platform, GNS, unexplained (it's Chess.com's AI knowledge and agent platform). The second had a line the cold reader called "polished and generic". The third was the first one the cold reader read correctly: what I do, what I built, and what I want.

4. Nothing goes out without me

A prompt is a suggestion. A hook is a guarantee. Before every tool call, a hook in code refuses anything that would submit a form, type into one, send a message, publish a page or push code. When it refuses, the desk saves the thing as a draft and tells me.

The only way through is a one-off go I type in my own terminal. It covers one action, lasts ten minutes, and is used up. An agent that tries to write that go for itself is refused too.

5. Graded against my own answers

To know if the writer sounds like me, it answered eight questions blind. I already had answers to all eight. A second agent graded each one against mine, on substance, facts, voice and register (whether the length and tone fit the form).

It ran three times. The first passed 3 of 8, and facts did worst: three answers got a fact wrong, one gave a reason I never gave. Giving the writer the reader's notes first made it 4 of 8. Giving it how I write and decide made it 5 of 8, with facts at their best yet (3.25, then 4.00, then 4.25).

Read that loosely. The grader moves about a point per case between runs, and the fifth pass sits exactly on the line. Two things didn't move. Substance stayed at 3.12 all three times: on two questions the writer leads with a different project than I did. And register fell, because it ends form answers with a question to the reader. Both are fixes for the desk, and they're why every answer still comes to me.

Where the data said otherwise

  1. My own habit reads as AI.Twice, the cold reader flagged a neat reversal as machine writing, the last time "not X, it's Y". It's how I write in Slack. The desk doesn't decide for me; it marks the line and asks.
  2. The writer's word count was wrong.It counted 94 words by eye; there were 104. Now the editor counts with a tool, not by eye.
  3. The answers I graded against were drafts.They were drafted with Claude for me to edit. Scored against fifteen things I wrote myself, they average 2.75 to 3.25 of 5. A real voice eval needs answers that are only mine.
  4. Facts failed before voice did.The writer mostly sounded right and got details wrong. So the editor's first job is the fact-check, before any score.
  5. Knowing how I write didn't change the voice score.Voice held at about 3.6 across all three runs, even after the desk read the captain's study of my writing. What moved was facts, and most of that came from the reader's notes, not the study.

How it's built for engineers

  • Five Claude Code skills, one SKILL.md each, in one repo. Each question is a run folder: reader notes, numbered drafts, numbered editor reports, a final.
  • The gate is a PreToolUse hook in Python, modelled on the captain's. It classifies each call (submit, fill, send, publish, push, merge) and logs every decision. 67 tests run against a throwaway ledger.
  • The facts file cites a single table of figures, so the desk and the portfolio can't disagree.
  • The cold read is a subagent given only the question and the answer: no files, no tools.
  • The eval kept the reference answers outside the repo until every blind answer was written.

Where it stands

Version 1, on my laptop, used once for real. The voice eval is at 5 of 8 after three runs, so nothing it writes goes out unread. Next: fill in the file only I can write, grade it against answers that are only mine, and run it on the next application.
