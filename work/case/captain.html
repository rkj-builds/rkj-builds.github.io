The problem

Four brands, one designer. A morning starts with a pile: review requests on GitHub, questions in Slack, tickets in Jira, each from a different team, each waiting on me. The real design work only starts once the pile is cleared, and the pile is mostly the same kinds of thing, every day.

I wanted the groundwork done before I sat down, done the same careful way every time, and I wanted to be sure nothing went out in my name without me reading it.

1. The crew, and who does what

Six agents, each with one job, running on a schedule every weekday morning. The board is drawn as a yacht deck, so they have boat names: a skipper per brand, a lookout, a copywriter, and me as the captain.

  • Four skippersOne per desk: The Moorings, Sunsail and Le Boat, plus one for Helix, the design-system platform. Each takes the tickets and reviews for its brand and does the groundwork.
  • Skye, the lookoutChecks Slack, Jira and GitHub every hour and keeps one inbox of everyone waiting on me, longest wait first.
  • Wren, the copywriterWrites everything that leaves in my name, in my voice, and gives every draft a last pass. She never posts.
  • Me, the captainI read the drafts, change what needs changing, and decide. Only I can send.

2. Growth design, the skill the skippers run

The Moorings and Sunsail desks get growth tickets: change a page, move a number. I wrote down how I work a ticket as one Claude Code skill, so every ticket runs the same loop: eleven steps from intake to readout, with six stops where I decide: how big the ticket is, which number it should move, which ideas to try, the plan, and two checks before anything ships. The skippers run it; at every stop, they wait for me.

Its first ticket was a paid landing page for yacht charters. The data showed 81.5% of paid visitors were on phones and the photo gallery was the most tapped thing on the page, so the design put the photo first, asked about the trip before contact details, and shipped version 1 as the control for the test.

3. Nothing goes out without me

A prompt is a suggestion. A hook is a guarantee. Every action an agent takes passes a gate in code before it runs. It always refuses to merge a pull request. When I'm not there, it refuses every post, comment or push unless that item carries my approval.

Trust is earned per desk and per kind of action, not switched on for the whole crew. A desk moves up a level when 95% of its last 20 drafts of that kind went out unchanged and its evals pass. One reversal moves it back down.

4. Graded against what I actually did

To know if the crew is any good, I took 46 real situations from my own work history. The crew answers each one blind, and the answer is graded against what I really did, on seven dimensions.

The third run passed 10 of 46. Judgement calls scored 7 of 8; Jira and pull-request replies scored none. That is why every desk is still at level one, and why every draft still comes to me.

5. A board you read at a glance

An agent you can't see is an agent you won't trust. The board shows the crew as a game: a skipper on a ticket leans in and types, idle desks stay dark, and the plaque counts what needs me. Motion only where something changed.

The art was a second experiment: Claude Code wrote the brief and Codex drew to it, 52 images from 60 attempts.

Where the data said otherwise

  1. A dashboard meant reading every row.The first version was a table of statuses. To know if anything was wrong, I had to read all of it. So it became the board: who is working, what is waiting on me and what went out, in one glance.
  2. The first scheduled run froze.It stopped on a permission prompt with nobody there to answer it. Now unattended runs never ask; anything that would need asking is refused, and a stall alarm fires after fifteen minutes of nothing.
  3. Clicking around a live site counted as real visits.A desk checking a page fired real analytics events. Production is now look-only for the crew.
  4. 10 of 46 is not good enough.The plan was to promote desks as they earned it. The evals said none had. So none were promoted, and the score is shown here as it is.

How it's built for engineers

  • Claude Code on a schedule. A morning shift on weekdays; the lookout runs hourly. Skippers work in their own git worktrees, up to three at once.
  • The gate is a PreToolUse hook in Python with its own tests. It logs every decision; its first ever was refusing a merge.
  • An autonomy ladder per desk and per action: shadow, drafter, trusted, autonomous. Promotion is a rule in code, not a judgement call.
  • Evals: 46 situations, answered blind, graded on seven dimensions against what I actually did.
  • The board is one HTML file with no framework. The deck and the chart table are two views of one store, so they can't disagree.

Where it stands

Running every weekday. Every desk is at level one, so every draft comes to me. The growth-design skill has run three tickets; the landing page's version 1 has been live as the control since 14 October, and its test has not reported yet.
