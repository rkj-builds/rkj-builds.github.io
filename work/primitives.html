The slot picker, built in the open

Project 831 takes bookings in one time zone and rejects any other. Here is that shortcut done properly: four booking components for coss ui, on Base UI, written the way the library writes its own. Dates belong to the venue and times belong to whoever is booking.

Oct 2026MineReact, coss ui, Base UI, Intl35 tests, no axe violations

What page 06 left open

Project 831's venue has no daylight saving, so its slot maths uses a fixed offset, and a rule naming any other zone is refused. That was the right call for one venue. It is the wrong one for a scheduling product, where the person booking is rarely where the court is.

So I rebuilt the hard part as components, in coss ui's own shape: one file each, Base UI underneath, its tokens and dark mode, a data-slot on every part. The zone maths is under 300 lines on Intl, with no date library.

The week the clocks change

A weekly booking is a time on a wall in a named zone: Monday 07:00, Asia/Kolkata. Stored as a list of instants, it drifts an hour the first time anyone's clocks change. Stored as a rule, the venue's 07:00 stays 07:00, and what changes is what it means to you.

The preview shows the next dates in both zones and marks the row where that changes. New York leaves daylight saving on 1 November, so from 2 November the booking is 8:30 PM, not 9:30 PM, for someone there.

Four components, one file each

coss's Calendar wraps a third-party day picker, which is good at picking a date. A booking calendar needs more on each day: how full it is, what it costs, and a full day that stays readable instead of disappearing. That meant owning the grid. Everything else composes Base UI.

What each one is built on, and what it adds

AvailabilityCalendarIts own WAI-ARIA grid, coss ButtonStatus, price and a spoken description on every day. The week starts on the locale's first day.

Past the spec

Testing Library tests cover every keyboard path, and axe runs on each component. In the browser, axe found two things the unit tests couldn't, and both are fixed:

  • Label in name. A day button showed "20 ₹1,200" while its name read "Tuesday, 20 October 2026, ₹1,200 an hour". Someone using voice control says what they see. The price now sits outside the button, so the button's visible text is the day number and its name contains it (WCAG 2.5.3).
  • Dark muted text. coss's dark muted grey measures 4.42:1 on a card, just under AA. Mixing it 80% instead of 90% gives about 5.3:1.
  • A 12-hour clock behind the venue. "10:30 PM −1 day" wrapped inside its pill. It only shows for a 12-hour viewer whose times cross midnight, who is exactly who the mark is for. The mark now sits on its own line.

What it is in practice

  • A public repo with the booking demo, the docs and the tests. pnpm dev runs it.
  • 35 tests: date maths, spring-forward gaps and repeated autumn hours, month-end clamping, recurrence across clock changes, keyboard paths and axe.
  • No date library. Offsets come from Intl's formatToParts, local times resolve the way Temporal's "compatible" option does, and the API is shaped so swapping in Temporal is small.
  • Example data: one court, open 06:00 to 22:00 Bengaluru time, made up and deterministic. Nothing here books anything.

Dates belong to the venue. Times belong to you.
