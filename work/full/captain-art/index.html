Creating the art for my AI crew

Three tools, each on the job it does best. Claude Code set up the workflow and wrote the briefs. Codex generated the art with OpenAI’s built-in image tool. Scripts back in Claude Code made it behave on a page.

I set the direction, approved the reference and made the calls on what shipped.

1.

Set up the workflow: each tool on its own job

The captain lives in Claude Code: the repo, the scripts, the page. That is where I build. Claude Code does not make images, so I did not ask it to. Codex has OpenAI's image tool built in, so the art went there.

The tools never talk to each other. Files do the handing over. One prompts file is the single source of truth, a task file tells Codex what to do with it, and stable filenames tie every image back to its prompt and its review. Codex writes to one folder; Claude Code reads from it.

My part is the direction and the calls: what the world looks like, which reference wins, what is kept, what gets fixed and what gets dropped.

The result was 56 original PNG masters: one approved reference, an empty yacht, six human profiles, a gull mascot, expression edits, furniture, props, textures and architectural pieces. [1][4][5]

  1. DirectMe. The world, the palette, the camera, and what each piece is for.
  2. BriefClaude Code. A prompts file, a brief page and a task file for Codex.
  3. Generate and gradeCodex, with OpenAI's built-in image tool. It checks every image against the task file and writes a report.
  4. Process and buildClaude Code. Scripts trim, fix and tile the art, and inline it into one HTML file.
  5. Review and decideMe. What ships, what gets fixed in code, what gets dropped.
2.

Start with what code can draw

Version one was pixel art drawn in code: a Python renderer in Claude Code, 480 by 300 art pixels, with a design canvas of day, night, crew and phone artboards. It proved the layout and the idea. It looked flat.

Richer art was a job for an image model, so the work moved there instead of pushing the renderer further.

3.

Design the brief, not the pictures

Before any image, the brief. One style paragraph sets the palette, outlines, light and camera. A person block keeps every crew member in the same seated framing. An isolate block keeps objects alone on transparency. Then one line per asset, in groups: the world, the crew, desks, props, decor and papers.

It is written as a page, every prompt with a copy button, with notes for ChatGPT, Gemini and Midjourney. The brief does not depend on one tool; Codex is the one I chose to run it.

A motion plan sits in the same brief: a breath every few seconds, a blink at random, plants that sway a degree or two, a sailboat crossing now and then. The art was briefed for how it would move, not only how it would look.

Then a task file for Codex: the anchor first, everything else against it, blinks edited from their own base, every image checked against six rules, a report at the end. Write only to one folder. Do not resize or post-process. Do not commit or push.

4.

Approve one visual reference before expanding the set

I began with a small scene containing a desk, a person, a plant, coiled rope and water. That tested several materials together. The first reference was rejected because the rendering was too smooth and the shirt contained an emblem. The second reference was selected and approved. [1][2]

The direction was warm, readable pixel art: honey teak, cream, sage, terracotta, navy and brass; dark warm-brown outlines; stepped pixel edges; restrained shading; and light from the upper left. An elevated three-quarter camera showed the tops of objects while retaining enough of their fronts to read their shape.

Every subsequent base asset used that approved reference. The prompt separated style from content: match the palette, outlines, shading and camera, but draw only the requested subject. That kept the reference’s desk and plant from becoming unwanted additions to every image. [1]

Match the art style, outline colour, shading and palette of the reference image exactly, but draw only the subject described above.
5.

Break the world into reusable pieces

I separated the environment, people, furniture and small objects. The yacht was generated empty. People were seated with their hands at keyboard height, without a desk in the image. Desks contained their specified accessories but no person. This gave the implementation separate pieces to arrange and layer. [1][3]

Shape and view followed the subject: square canvases for most isolated objects, wider compositions for the yacht and dock, long strips for bunting and architectural sections, and both rectangular and circular rugs. Furniture used the elevated camera; floor textures, rugs and papers used an overhead view.

Most pieces were generated with real transparency and generous margins. Background textures and the reference scene remained opaque. I preserved the native image canvases for handoff instead of silently resizing them to the dimensions requested in the brief. [2]

6.

Give the crew distinct profiles and expression states

The six human profiles were the owner, the Moorings skipper, the Sunsail skipper, the Le Boat skipper, the Helix skipper and the copywriter. Clothing, hair and accessories distinguished them: white shirt and glasses, navy polo, red cap and polo, teal polo with sunglasses, purple knit with headphones, and terracotta knit with a pencil. Their seated framing and proportions remained consistent. [1][2]

Each human received an eyes-closed edit. The gull received a base image, a blink and an open-beak talking edit. Each expression was edited from its own base image rather than generated as a new character.

The edits were visually aligned, but small pixels and shading changed outside the intended facial region. All eight expression edits were flagged for finishing against the stricter requirement that only the eyes or beak change. The original canvases and that limitation travelled with the handoff. [2]

7.

Codex grades its own work; I review the grades

The task file gave Codex six reasons to regenerate an image: text or a logo, more than one subject, the wrong camera, a background that is not transparent, a blink that changed more than the eyes, a style that drifts from the anchor. It checked every image and wrote a report.

Review checked more than whether an image looked appealing. I checked the silhouette, camera, palette, transparency, object count, framing and unwanted lettering. The recorded corrections included the gull’s cap colour, extra bookshelf ornaments, the crate and easel perspective, and the coffee cart’s contents. [2]

The initial batch retained 52 masters across 60 recorded generation attempts. The report marked 43 as passing and nine for finishing: the eight expression edits and the sea texture. Flagged images were kept, not hidden. These figures describe the original batch; they do not include the four later architectural images. [2]

The sea texture was retained after three attempts because its style and palette worked, while its opposite edges were still not pixel-identical. It went forward as a candidate requiring seam finishing, with that limitation recorded. [2]

8.

Extend the same style into modular shapes

A full-screen deck needed more than the first batch: floors that tile, a rail and hull for the edges, walls and glass. Nine more pieces went into the same prompts file, and the same task file ran again. It skipped what existed and made only the new ones.

Four of them are in this library: a teak deck texture, a cream cabin floor texture, a straight yacht rail and a glass wall. Their prompts reused the approved reference, palette and pixel treatment. Floors used a flat overhead view; the rail and glass wall used long horizontal compositions. [4]

The additions log records prompts, dimensions and transparency. It does not assign the individual pass grades used for the original batch.

9.

Back in Claude Code: make the art behave on a page

Generated art is not ready for a page. Scripts in Claude Code take it the rest of the way, and never touch the originals.

Every sprite is trimmed to its visible pixels, sized to about three times its size on screen and saved as WebP. Blink and talk frames are rebuilt from their base: only the pixels inside the head or beak come from the edit, so nothing else shimmers. The yacht is cut from its painted sea by a flood fill that stops at the hull. The sea tile loses its painted margin and is rolled so the seams meet in the middle, then covered with dithered pixel blocks. The wake foam and extra floor textures are drawn in code, in the palette of the generated yacht. Every sprite is inlined into one HTML file.

The eight flagged expression frames and the sea seam were fixed here. The originals keep their flaws; the fixes live in code and run again whenever the art changes.

10.

The same move for the interface

The workflow held for the front end. Claude Code wrote a second brief, for Codex to prototype the full-screen deck with dummy data: plain HTML, CSS and JavaScript, no framework, read the art without touching it, write only to its own folder.

Neither of Codex's designs shipped as it was. Both changed what did. I kept its buttons, its panels with a close button and the glow on hover, and matched the type to it. I dropped the walls: the crew works on one open deck. Its app became the Chart table, rebuilt on the board's own data.

11.

Hand the assets over with their context

The asset handoff contained all 56 original PNGs, copied without resaving. Stable filenames connected each image to its prompt and review notes. The supporting manifests recorded file hashes, transparency and dimensions. The approved reference remained in the pack so later additions could follow the same direction. [5]

The handoff also carried the practical finishing notes: expression frames needed stricter pixel consistency, the water needed seam work, and faint alpha noise could affect later cropping. The full library stays available even when a composition uses only a subset. [2][5]

What carries over to any project: pick the tool for the job, not the job for the tool. Brief in files, so any tool can pick the work up and a rerun only fills the gaps. Let models generate and grade; keep the direction and the calls.
