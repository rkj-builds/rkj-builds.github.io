Ten tools, one dock, and a way in

Helix renders a brand's real pages, and once it did, everyone wanted to do something to the page in front of them. I built the dock they live in, the kit they draw from, and the skill that builds the next one.

Oct 2026Mine10 tools, 1 registry, 1 skillhelix/chrome/toolbar/

Why a toolbar at all

Helix shipped without tools. A designer would see something wrong, screenshot it, paste it in Slack and describe where it was. The thread outlived the fix.

The obvious patch is a button on the page that needs one. Do that twice and you have two shortcuts and two opinions about what a panel is. So I built the dock first and the tools second.

Comments, which is why the rest exist

Sign-off happened in a call: a shared screen, three people talking over each other, and one of them typing notes nobody could tie back to a pixel.

Comments pins the feedback to the element. A stakeholder opens the link, signs in with the work account they already have, and leaves a note on the thing itself. No install, no repository, no Figma seat. Identity is verified, so a note carries a name, and the allowed domains are enforced in the database rather than the browser, because a shared link is a shared link.

Annotate, the same idea pointed the other way

Comments are for people. Annotate is for the agent: private notes that never leave your machine, built around the copy button.

A note carries what you typed and what you clicked, which is the component path, the file and the line. So ReviewsCarousel › ReviewCard › hr and "stars should sit on the baseline of the name" arrive as one prompt, and nothing has to guess which hr you meant. The categories are there so a pass can be batched: collect six spacing notes, send them once.

Seven more, each answering one complaint

  • Inspect ⇧I  "What is this and where does it live." Engineers kept asking designers which component a thing was, and designers kept not knowing. Now the page answers: name, size, spacing, colour tokens, the classes and what they resolved to, the file and the line.
  • Changes ⇧D  "What moved since Friday." Reviewers were re-reading whole pages to find one edit. It marks what changed here since your last visit, since main, or since the last commit.
  • Snap ⇧S  "I need this in the deck by eleven." People were cropping browser screenshots by hand and catching their own scrollbar. It copies the view or the full page at a chosen width, through the same headless browser that takes the exploration thumbnails, so a deck and a card cannot disagree.
  • Layout grid ⇧G  "Is this on the grid or near it." The design system's own columns and gutters over any page, so the argument is settled by looking.
  • Outlines ⇧O  "Which of these is actually a component." Every component on the page gets an outline, so the library and the one-off markup stop looking alike. It keeps up when the page changes under it.
  • Brand ⇧B  "Show me this in the other brand." A full-screen page has no sidebar to switch themes from, so the switch lives on the dock and the page repaints in place.
  • Copy link ⇧L  "Send me that." The address of the page in view, in one click, opening the same page for whoever you send it to.

Pick, which changed how decisions get made

Five variants and six opinions used to resolve into whoever spoke last. Pick makes the choice a record: everyone with the link picks one and says why, the tally is visible, the author decides.

After that only the author can change it. A deployed preview has no git history to say who owns an exploration, so the first person to decide owns the decision, and the database enforces it rather than the browser.

Pick and Comments are the two that need sign-in, so a signed-out dock carries seven of the ten. The registry doing its job: a tool says what it needs, and a context that cannot run it does not offer it.

The part that is actually the work

Ten tools is not the achievement. The tenth costing an afternoon is.

A tool is one entry in one registry, and that registry is what the dock renders, the catalogue lists, the sidebar counts and the keyboard scheme reads, so a tool cannot exist in one and be missing from another. It declares a shape, an audience, a shortcut, and what it needs to run. That last one is why a tile can say needs a dev server and the dock greys it out instead of failing on the click.

Every value a tool reaches for has a name, including the ones people hard-code. A tool that needs one the kit lacks adds the token and its line of documentation in the same change. Motion included, because the alternative is ten tools easing ten ways.

And a skill, so it is not my toolbar

A guide gets read once. I wanted the next tool built by someone who never read it, so the build is a skill.

A designer says "build a tool that measures the distance between two elements". The skill settles shape, audience and shortcut in one exchange, stands up a sandbox running this chrome, builds inside the kit, and opens the pull request. It refuses to run inside a brand's repository.

That refusal is the design. A tool written into one brand is invisible to the other nine and is wiped by the next chrome update, so the refusal is the difference between one toolbar and ten forks of one.

Ten tools, one dock, one shortcut scheme, and nobody has to be told where the eleventh goes.
