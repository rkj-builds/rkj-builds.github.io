Ten brand teams, one workspace

Helix is where the design system lives now: tokens, components, layouts and explorations, rendered from each brand's own repository and shared as a link.

2026MineNext.js 16, React 19, Tailwind v4Chrome 2.0, ten brand teams

What it is

Helix installs into a brand's Next.js repository and renders what is already in it. Folders become navigation. Every specimen, layout and exploration is a URL, opened with nothing installed.

Before it, a design was a picture handed to an engineer, and the picture and the build drifted apart. Figma still holds brand assets. It stopped holding the system.

One workspace, every brand's own system

Helix holds no brand. Each install reads its brand's own token stylesheet and draws the palette, type, spacing and radius from it, so every workspace looks like its brand and works like all the others. A new brand is an install, not a project.

Nine brands have built their systems in it so far. Others, like Hayes & Jarvis, are still on the starter tokens every install begins with.

Each brand's own token stylesheet, rendered by Helix chrome 2.0. The brand workspaces themselves run chrome 1.0.9 to 1.4.0, each updating on its own schedule.

What I obsessed over

The design-system page has no content of its own. It reads the brand's token stylesheet at request time and draws the ramps, the semantic set, the type scale and the spacing from it, grouped by the comments above them. There is nothing to publish and nothing to keep in step, so the page cannot tell you something the code does not.

Appearance sits on top: light and dark, and five accents, each a pair that clears AA as text on every surface. The accent from the original artboard measured 3.4:1, so it was replaced rather than shipped.

A component has a page, not a card

Each component gets its specimen in a frame, its props read off the type with the JSDoc and the destructured defaults, and every file that imports it. Owner, file and last change come from git. Nothing on it is written by hand, so it is right on the day someone reads it.

The preview, which exists because of review calls

Sign-off happens on a shared screen. Someone presents a design at desktop width, and four minutes in, somebody asks what it does on a phone. The presenter resizes the window, loses their place, scrolls back, and by the time they find the section the room has moved on to something else. That happened in nearly every call.

So the preview opens both at once, and I built each control against a thing that was going wrong:

  • Desktop, Tablet, Mobile, Both. Four fixed widths, not a draggable handle. A dragged handle means every reviewer sees a different page and the notes cannot be compared.
  • Sync scroll, on by default. The question is almost always the same section at another width. It turns off for the rarer case, comparing two different parts of a page.
  • The exact size and the zoom, written on the frame. 1440 × 1000 at 72%. It ends the recurring argument about whether what is on the projector is real size.
  • The variant switcher stays inside the page. It is the exploration's own panel, so a stakeholder steps through five directions, and toggles a piece on or off, without the presenter leaving the link or opening a second tab.
  • Width and variant live in the URL. The link pasted into the recap reopens on exactly what the room was looking at, which is the difference between a decision and a reminder to have the meeting again.
  • Esc exits. Presenting is the main use, so the exit is the key people press by reflex.

What it changed

Review stopped producing a follow-up thread. The questions that used to end a call with "can you send me the mobile version" get answered while everyone is still in the room, and the link in the recap opens on the frame that was agreed. Sign-off moved into the call it was always supposed to happen in.

What happened

  • Ten brand repositories run it, plus four production site repositories where engineers promote Helix layouts straight into the live frontend.
  • Designers ship the pull requests. 290 merged across the brand repositories in six months, from sixteen people, most merged the day they opened.
  • The accessibility gate runs on every build, every page against every theme, and it was never lowered. It was switched off once for being slow, so we scoped the loop instead.
  • 2.0 is the workspace on this page. Sign-in, the redesign, the toolbar and the ten tools in it: 155 files, with a security pass before anyone looked at it.

A design system you have to publish is a design system that is already out of date.
