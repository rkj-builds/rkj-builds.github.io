A crew that does my solo work

Four brands, and I am the only designer on most of them. So I built a crew of agents that works my queue before I log on and drafts in my voice, and a board to run it from. They draft. I decide.

Oct 2026MineClaude Code, hooks, scheduled runs, one HTML fileRunning every weekday

Why a game, for a tool

An agent you cannot see is an agent you will not trust. The first version was a dashboard of statuses, and I had to read every row to know if anything was wrong.

State you can see beats state you have to read. Who is working, on what, what is waiting on me, what went out: one glance.

Motion, and where there is none

The board is open all day beside real work, so motion has one job: to mark a change of state. Anything you read or act on holds still.

Two views, one store

The office is for glancing. The chart table is for getting through it. Both read the same store and call the same actions, so an approval on one is the approval on the other.

Each published page owns its own data, so two apps would have drifted by the second day. One source of truth; a view is only a way of looking at it.

Drafts, never sends

A prompt is a suggestion. A hook is a guarantee. Every tool call the crew makes passes a gate in code before it runs.

# hooks/gate.py, a PreToolUse hook
#
# Always: deny merging a pull request.
#
# Unattended runs: every outward write is denied
#   (Slack post, Jira write, git push, PR open or
#   comment, typing into a browser)
# unless the item carries Rahul's approval,
# or the desk has earned level 2 for that action.
#
# The lookout writes nothing outward, reactions included.
# Every decision goes to ledger/gate.log.

Trust is earned per action

Autonomy is a ladder for each desk and each kind of action, not a switch for the whole crew. Replying in Slack and pushing a branch are not the same risk.

  • L0ShadowDrafts, compared with what I actually sent. I never see them.
  • L1DrafterEvery draft comes to me. Where every desk is today.
  • L2TrustedActs, then tells me. Low-risk work only.
  • L3AutonomousActs alone, for that one kind of action.

A desk moves up when 95% of its last 20 drafts of that kind went out unchanged and its evals pass. One reversal moves it down. The likeness evals, replayed from my real history, score 9 of 46 today. That is the baseline the crew has to beat, and why nobody is past L1.

Scheduling is the hard part

A shift at 08:31 on weekdays, a lookout every hour from 09:30. The first real run froze on a permission prompt nobody was there to answer. Because it never finished, the next morning's run never started.

A run that cannot ask must never need to, and a stalled run has to fail loud. The same rule I keep for a booking system's cron.

  • No prompts in unattended runs. Read-only reach where it can be, the gate for everything else.
  • A stall alarm. Fifteen minutes with no activity is reported, not waited out.
  • Production is look-only. Added after a desk clicked a control on a live brand page and sent real analytics events. Clicks and tracking checks run on QA or a preview.

How the art was made

Version one was pixel art drawn in code. It worked, and it looked flat. For version two I wrote the brief, Codex made the images, and scripts made them behave on a page.

  1. BriefOne style paragraph, one line per asset, written as a page with a copy button each.
  2. AnchorOne image first. Every later image is generated against it.
  3. Generate and reviewCodex makes the set and grades it; flagged images are kept, not hidden.
  4. Cut, fix, tileScripts trim and size the sprites, repair the blink frames, cut the boat out, make the sea repeat.
  5. InlineEvery sprite goes into the one HTML file. No requests, nothing to host.

What it is in practice

  • Six on the crew. Four brand skippers, Wren who writes everything in my voice, and Skye who watches Slack, Jira and GitHub for anyone waiting on me.
  • Nine minutes for the first full shift, scan to brief. Nothing posted.
  • 34 gate checks run on every change: what must be refused, and what must still get through.
  • Keyboard first. J and K move, A approves, E edits, P parks, Escape backs out. Every control is named for a screen reader, and reduced motion holds still.
  • One HTML file. No framework. The sprites are inlined, the store is the page's own.

They draft. I decide. The gate makes sure of it.
